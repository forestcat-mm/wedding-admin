# 受付 v2.3：受付ボタンの確認ポップアップ

受付済ボタンを押したときの流れを、確認ポップアップ1枚に変える。v1 で入れた「お渡し物があります」の確認ダイアログは、このポップアップに置き換える。

## ポップアップの内容
受付済ボタンを押すと、画面中央にポップアップを開く。
- 氏名（大きく）、ローマ字、サイド、卓・席、受付ID（受付IDが ON のときのみ）
- 同行者（v2.1 と同じ形式。子どもは年齢付き）と人数「計n名」
- お渡し物（ある場合のみ表示）
  - 見出し「お渡しする物があります」。背景色と太字で、ポップアップ内で一番目立たせる
  - 1 件ずつ大きなチェックボックス（例：☐ お車代　メモ：封筒は新婦母が保管）
  - すでにお渡し済の項目はチェック済みで表示する
- ボタンは「受付」と「キャンセル」

## 「受付」を押したとき
- お渡し物に未チェックのものが 1 つでもある場合：受付しない。お渡し物欄に赤字で「お渡しが済んでいません：お車代」のように項目名を出し、未チェックの項目の枠を赤くする。ポップアップは閉じない
- すべてチェック済み（またはお渡し物なし）：チェックしたお渡し物を「お渡し済」として保存 → 受付済を保存 → ポップアップを閉じ、行を受付済の表示にする

## 誤操作の防止
- PC：Enter で「受付」、Esc でキャンセル。開いてから 0.5 秒間は Enter を受け付けない
- スマホ：ポップアップの外をタップしても閉じない（閉じるのはキャンセルのみ）

## その他
- 受付の取り消しは従来の確認ダイアログのまま
- 行のお渡し済トグルは今までどおり単独でも使える
- 通信失敗時は未送信・再送の仕組みに乗せる
- PC・タブレット・スマホで同じ流れ

## 実装メモ（2026-09-25）
- 判定は `public/reception/checkin-logic.js`（`planCheckin`、`enterAllowed`）に切り出し、`tests/checkin-logic.test.mjs` で検証。`npm test` は Worker のテストと合わせて実行
- ポップアップは `#ckpop`（reception.js の `openCheckinPop` / `submitCheckinPop`）。送信はお渡し済 → 受付済の順でキューに積む
