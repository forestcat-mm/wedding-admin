# ご祝儀 v2：出席者の仮登録と受領確認 — wedding-admin

ご祝儀の記録方法を「出席者を仮の金額で自動的にリスト化し、受領確認ボタンで実績にする」形に変える。
`00_spec/gifts.md`（v1）がある場合、ご祝儀の登録方法と予算連動はこの仕様で置き換える。内祝いの手配（gift_returns）とセキュリティ要件はv1のとおり。v1が未実装なら、v1の内祝い部分も含めて実装する。

## 前提
- SQL適用済み（`gifts-v2.sql`）
  - `gifts`：source（attendee／manual）、status（expected＝仮／received＝受領済み）、expected_jpy（仮の金額）、amount_jpy（実績額）、received_at、received_by ほか
  - `gift_givers`：1行＝贈り主1人。出席者は reply_person_id、欠席の招待客は guest_id、それ以外は name。1人の出席者が入るご祝儀は1つだけ（一意制約）
  - `app_settings.gift_default_jpy`：仮金額の既定値（30000）
- **実装前に、予算タブの現在の「ご祝儀見込み（30000円×人数）」と「ご祝儀が1件でもあれば収入を切り替える」処理の場所を特定して報告すること。** 既存の見込み額の設定値があれば、gift_default_jpy と統一する方法を提案する

## 1. 出席者の自動リスト化
- 対象：有効な回答（replies_admin.deleted_at is null かつ superseded_by is null）の reply_people のうち、deleted_at is null かつ attending = true の人
- ご祝儀タブを開いたとき（または「出席者を同期」ボタン）に、まだどの gift_givers にも入っていない出席者について、1人1件の gifts（source = attendee、status = expected）を作る
  - 本人（idx = 0）：expected_jpy = gift_default_jpy（30000）
  - 同行者（idx > 0）：expected_jpy = 0
  - side は、紐付くゲスト（matched_guest_id）の side、なければ replies_admin.side
- 出席者が欠席に変わった・削除された場合
  - status = expected なら、その gifts を論理削除する
  - status = received なら削除せず、「出席者ではなくなりました」の警告を付けて残す
- 同期は何度実行しても重複しない（冪等）ように作る

## 2. 受領確認
- 各行に「受領」ボタンを置く
  - 押すと、status = received、amount_jpy = expected_jpy、received_at = 現在時刻、received_by = ログインメールを保存する
  - **30000円をいただいた場合は、ボタンを1回押すだけで完了する**
- 金額が違う場合
  - 行の金額欄をその場で編集できる（受領前は expected_jpy、受領後は amount_jpy を編集）
  - expected_jpy が 0 の行（同行者など）で「受領」を押したときは、金額入力の小さなポップアップを出す
  - 外貨の場合は、詳細画面で通貨・受け取った金額・円換算額を入力する
- 受領の取り消しボタン（確認ダイアログ付き）。取り消すと status = expected に戻し、amount_jpy・received_at・received_by を null にする
- 表書きの名義、種類、経路、内祝い要否、お礼状、メモは詳細画面で編集する

## 3. 連名（グループ化）
- 一覧で複数の行をチェックし、「連名にまとめる」を押すと、1件のご祝儀にまとめる
  - 先頭の行の gifts を残し、他の行の gift_givers をそこへ移して、他の gifts は論理削除する
  - まとめた後の expected_jpy は、各行の expected_jpy の合計（編集可）
  - 受領済みの行は、まとめる対象にできない（先に受領を取り消す）
- 連名の行は、贈り主を「A・B・C」のように並べて表示し、人数バッジを付ける
- 「連名を解除」：贈り主を1人1件に戻す。expected_jpy は、本人なら既定値、同行者なら0に戻す。受領済みの場合は解除できない
- よく使う操作として、同行者のいる行に「同行者とまとめる」ボタンを出す（本人と同行者を1件の連名にする）

## 4. 欠席・招待なしのご祝儀
- 「ご祝儀を追加」ボタンで手動登録する（source = manual）
  - 贈り主：欠席の招待客をゲスト一覧から検索して選ぶ（guest_id）か、名前を直接入力する（name）。複数人も可
  - 金額を入力し、そのまま受領済み（status = received）として保存する
- 手動登録した行には「追加」ラベルを付ける

## 5. 一覧と集計
- 列：贈り主、表書きの名義、サイド、金額、状態（仮／受領済み）、内祝い状況、お礼状
  - 仮の行は金額を薄い色で表示し、「仮」ラベルを付ける
  - 受領済みの行は金額を通常の色で表示し、受領日時を小さく添える
- 絞り込み：状態（すべて／仮のみ／受領済み）、サイド、友人圏、出席者・追加、内祝い状況
- 並び替え：名前、サイド、金額、受領日時
- 上部の集計カード
  - ご祝儀の合計（受領済みの実績額 ＋ 仮の見込み額）
  - 内訳：受領済み x件・¥a ／ 仮 y件・¥b
  - 新郎側・新婦側の内訳
  - 内祝いの購入額合計、未手配の件数

## 6. 予算タブとの連動（現行の処理を置き換える）
- 現在の「ご祝儀見込み＝30000円×人数」と「1件でも登録があれば実績に切り替える」処理は廃止する
- 予算タブのご祝儀（収入）は、次の式で毎回集計する
  - 収入 = Σ（受領済みなら amount_jpy、仮なら expected_jpy）。対象は論理削除されていない gifts
  - 予算タブには「ご祝儀：¥合計（うち受領済み ¥a／仮 ¥b）」と表示し、「自動」ラベルを付ける。クリックするとご祝儀タブへ移動する
- 内祝い（支出）はv1のとおり（gift_returns の商品代＋送料。状態が「予定」のものは除く）
- 予算タブ上でこれらの行は編集できない。予算データへのコピーはしない

## 7. 設定
- ご祝儀タブの上部に、仮金額の既定値（gift_default_jpy）を表示・変更できる欄を置く
- 既定値を変えたときは、「仮・出席者・本人・金額を手で変えていない」行だけ新しい既定値に更新する。確認ダイアログで対象の件数を表示してから実行する（手で変えたかどうかの判定のため、必要なら gifts に列を追加してよい。追加した場合はそのSQLを報告する）

## 完了条件
- ご祝儀タブを開くと、出席者全員（本人は30000円・同行者は0円の仮）が並ぶ
- 「受領」ボタン1回で、30000円の実績になる
- 連名にまとめる・解除する、欠席や招待なしの方の分を追加する、の操作ができる
- 予算タブの収入が「受領済みの実績＋仮の見込み」で計算され、受領確認のたびに内訳が変わる
- 同期を何度実行しても、同じ人の行が重複しない
- 受付トークンの端末や受付APIから、ご祝儀の情報が見えない
- テストを追加し、npm test がすべて通る
